Dory's public README introduces the product. This guide covers work on the repository itself. To create a separate documentation site, use the [quick start](/getting-started/quick-start).

## Run the repository

```bash
git clone https://github.com/clidey/dory.git
cd dory
pnpm install --frozen-lockfile --ignore-scripts
pnpm dev
```

Edit Dory's own pages under `docs/`. Keep dependency lifecycle scripts disabled and preserve the repository's dependency integrity and release-age policies.

## Validate changes

```bash
pnpm test
node --import tsx --test bin/dependency-overlay.test.mts bin/preview-static.test.mts
pnpm build
node bin/dist/dory.js check
node scripts/verify-component-examples.mjs
```

The component browser check uses installed Chrome (or `DORY_CHROME_PATH`), measures preview padding and clipping, exercises tabs, and verifies math loading and failure states on desktop and mobile. It saves screenshots and a report under ignored `.dory/component-review/`; inspect these before publishing.

Review browser behavior in light and dark modes. For custom components, verify interactions and focus handling; compilation alone cannot do that.

## Preview the production site

```bash
pnpm preview --host 127.0.0.1 --port 3188 --strictPort
```

Open `http://127.0.0.1:3188/dory/`. Review code and the exact generated site before pushing or publishing changes.

## Publish this repository's docs

The documentation workflow validates pull requests and deploys main-branch documentation to `https://clidey.github.io/dory/`. Its canonical URL and path are configured in `docs/dory.json`; GitHub Pages uses GitHub Actions as the publishing source.

To deploy documentation without changing package versions, run the **Documentation** workflow manually on `main`.

Publish only the generated `dist/` artifact. Static Pages hosting includes navigation and search. Documentation chat and HTTP MCP need a separately hosted Dory server; do not put server credentials into static assets.

Imported MDX and component modules are executable source. Review them, build untrusted contributions without secrets or deployment credentials, and deploy reviewed artifacts separately. See the repository security policy for the trust boundary.

## Release the package

Run **Publish Package** on `main`. Choose **current** to release the version already recorded in `package.json` and `docs/dory.json`. This runs the validation, npm publishing, GitHub release, and Docker image jobs without incrementing versions or creating a version commit. The two version fields must agree.

Choose **patch**, **minor**, or **major** when the workflow should calculate and commit a new version. A current version older than an existing release tag, or a tag attached to another commit, is rejected. npm versions are immutable: an already published version is reused only when its package checksum matches the tested artifact exactly.
